# Capstone: PetalBank Credit Default Model in Production

Machine Learning for Data Science · about 10 hours

## Business use case

PetalBank approves personal loans in under a minute. Defaults run at about 6% and cost ₹1.1 crore a quarter. Build a model that predicts 12-month default at application time, choose an approval threshold that maximizes expected profit, explain individual decisions, check fairness, ship it behind an API and plan its monitoring.

## Data source

`petalbank_loans` is **Coral Petal synthetic data**, generated by [`../datasets/generate_petalbank_loans.py`](../datasets/generate_petalbank_loans.py) with seed 2026. No real customer data is used.

```bash
cd machine-learning-for-data-science
python datasets/generate_petalbank_loans.py --out datasets/data/petalbank_loans --seed 2026
```

| # | Table | Rows | Columns |

The data hides problems a real lender's data has: a column that leaks the outcome, missing values that are not random, repeat customers and drift. Finding them is part of the job.

## Ground rules

- **Split by time.** Train on applications before 2026-01-01; test on January to June 2026.
- **Profit rule.** A good loan you approve earns its net interest: `loan_amount × (interest_rate − 0.08) × term_months / 24` (0.08 is PetalBank's cost of funds; the balance averages about half the principal). A defaulted loan you approve loses `loan_amount × loss_given_default`. A rejected application earns nothing. Approve when the predicted default probability is below your threshold.

## Tasks

1. Framing canvas and baseline (Module 01).
2. Leak-proof preprocessing pipeline and leakage audit (Modules 02, 05).
3. Logistic regression, random forest and gradient boosting with time-based CV and Optuna tuning, tracked in MLflow (Modules 04, 06, 11).
4. Threshold chosen with the profit rule (Module 04).
5. SHAP explanations: global, plus three individual applicants with reason codes (Module 06).
6. Customer segments and default rate by segment (Module 08).
7. Fairness by age band and city tier, with a documented trade-off (Module 11).
8. FastAPI endpoint and batch scoring of the Q3 file with a drift report (Module 11).
9. Model card and a five-slide readout (Modules 11, 12).
