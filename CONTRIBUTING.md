# Contributing

Every change reaches `main` through a pull request. Nobody pushes to `main` directly.

1. Branch from an up-to-date `main`: `feature/<course>-<topic>` (for example `feature/stats-transcripts-module-01`) or `fix/<topic>`.
2. Commit in small, described steps.
3. Open a pull request into `main` with a summary of what changed and how it was checked.
4. Merge with **squash and merge**, so `main` has one commit per change and the PR keeps the full history.

**Approval (setup phase, from 2026-11-19):** pull requests are auto-approved. Claude opens and merges them so setup can move quickly, and every change stays tracked in a PR. When Rohit ends the setup phase, his approval is required before merge.

Merged feature branches are kept; they are only deleted when Rohit asks.
